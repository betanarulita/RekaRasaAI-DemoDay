# Content Planner UX audit follow-up

Mode: AFTER. Implemented approved findings 1–4 from [audit-001-2026-10-28.md](./audit-001-2026-10-28.md).

## Changes

- Output preferences are optional in the brief form and `/api/plan`; the legacy `formats` request field remains accepted.
- Planner plans may contain up to six freeform deliverables. Tasks include `selection_reason`; confirmation keeps title, format, channel, angle, and goal editable. Existing stored TikTok and marketplace task formats remain readable without a database migration.
- Planner instructions allow inference from the brief, include explicit preferences, and prohibit unsupported product details. Product facts returned by the model are retained only when their text is supported by the brief or project source text.
- Writer instructions now include focused guidance for poster/static ad copy, hero-image direction, campaign bundles, social content, short-form video, marketplace listings, and custom formats. Poster copy is returned as separate headline/body/CTA text; image text overlay is not implemented.
- Planner inference is completed before conversation/message/brief writes, so a model error does not leave a partial history record. A retry can start cleanly without duplicating a failed submission.
- Image tests select OpenAI explicitly through test patches, independent of the user's configured image provider. `.env` and credentials were not changed.

## Validation

- `python -m py_compile app.py test_app.py`: passed.
- `python -m unittest -q test_app`: 35 tests passed.
- Browser smoke check on a temporary local database: the brief page rendered with no selected preference, the “Plan my content” action was available, and opening the optional preference disclosure showed six standard choices and a custom format field. No live model request was made.

Tests cover a brief without preferences, poster output and unsupported facts, TikTok plus marketplace, custom output, selection rationale persistence, model failure/retry without duplicate history, legacy tasks, Writer/Reviewer/human approval, revision limits, and image-provider isolation.

## Remaining gaps

- Image text overlay/editor is still unavailable. Stable Diffusion output must not be treated as accurate rendered copy.
- No live Groq or ComfyUI call was made; automated model and image tests use fakes.
- `node` is unavailable in the current environment, so `node --check static/app.js` could not be run. The browser smoke check loaded the updated JavaScript and CSS successfully.
